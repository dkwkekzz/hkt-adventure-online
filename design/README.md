# hkt-adventure-online — 설계

엔진(`hkt-adventure-proto/web`)을 프로세스로 띄워 사람에게 여는 서비스다.
엔진이 밖에 내놓은 면(CLI · stdout 머리글 · Console 글 · Link · Store 레이아웃 · 자격)의 사실은 엔진 저장소의 `web/ONLINE.md` §1 이 들고, 여기는 그 위에 서는 서비스의 구조 · 흐름 · 책임만 든다.
엔진은 `engine.lock` 의 커밋 하나로 핀한다(`scripts/engine.sh`). 그 커밋의 사실을 코드로 베낀 것은 `src/protocol/engine.ts` 하나다.

## 목표

- 사람은 로그인하고 캐릭터를 골라 입장하면 관문의 주소 하나를 받아 바로 논다. 어느 호스트에 놓였는지 모르고, 존을 건너도 접속은 그대로다.
- 받을 수 있는 사람의 수에 구조의 천장이 없다. 사람이 늘면 프로세스와 기계를 늘린다. 프로세스 하나가 받는 수(상한)는 재서 설정에 두는 값이고 구조는 그 값에 기대지 않는다.
- 캐릭터의 진실은 서비스의 캐릭터 저장소다. 존의 진실(땅 · NPC)은 그 인스턴스의 Store 다. 서비스는 둘 다 안을 읽지 않는다 — 통째로 건네고 베끼고 되돌리기만.
- 게임 규칙은 서비스에 없다. 코드와 책임 · 흐름 문서에 게임 명사가 없다. 존 이름 · 데이터셋 경로 · NPC body 이름은 설정 값(`service.config.json`)으로만 든다.

## 원칙

1. 엔진과의 결합은 프로세스 경계다. CLI 인자 · stdin/stdout 글 · WebSocket JSON · Store 디렉터리 · 건넴 파일. 엔진 코드를 import 하지 않는다.
2. 클라이언트가 아는 주소는 둘이다 — 앞문(http)과 관문(WebSocket). 호스트는 안쪽 망에만 있다.
3. 사람의 글이 지나는 길(클라이언트 ↔ 관문 ↔ 호스트)에는 모두가 지나는 프로세스가 없다. 제어는 들어올 때 · 건널 때 · 떠날 때만 닿는다. 제어가 잠시 없어도 붙어 있는 사람은 계속 논다.
4. 상태는 저장에만 있다. 앞문 · 관문은 상태가 없어 수를 늘리면 되고, 제어의 표는 저장과 노드 · 관문의 보고로 다시 선다.
5. 캐릭터 하나는 한때에 호스트 하나만 든다. 그것을 지키는 것은 저장의 임대(Lease) 하나다.
6. 상태를 바꾸는 것은 흐름의 단계만이다. 모듈은 자기 책임 문서의 개념만 알고, 다른 모듈은 소켓(`src/protocol/`) 하나로 만난다.
7. 엔진에 손대는 것은 엔진이 "(밖)" 으로 비워 둔 자리를 채우는 것뿐이다(`ONLINE.md` §3.2).

## 말

| 말 | 뜻 |
|---|---|
| 존 | 닫힌 공간 하나. 데이터셋 하나와 설정 값(상한 · 여유 · NPC 묶음)이다. 엔진에게는 세계 하나다 |
| 인스턴스 | 존 하나를 도는 것 하나 — 호스트 프로세스 하나 + NPC 에이전트 프로세스 하나 + Store 자리 하나. 이름은 `<존>-<번호>`. 같은 존의 다른 인스턴스에 있는 사람은 서로 보이지 않는다 |
| 캐릭터 | 계정이 든 것 하나. 엔진이 명부에 적는 이름(`host.Account.id`)이 Character.id 다. 엔진에게는 사람의 묶음 하나다 |
| 건넴 | 캐릭터의 값을 인스턴스에 들이거나(들임) 인스턴스에서 거두는(거둠) 것. 값은 파일 하나이고 서비스는 안을 보지 않는다 |
| 임대 | 캐릭터의 값을 지금 누가(어느 인스턴스가) 들고 있는가. 번호가 늘기만 한다 |
| 노드 | 인스턴스를 띄우는 기계 하나 |

## 구조

모듈(책임)과 프로세스(띄우는 단위)는 다르다. 모듈은 `src/<모듈>/` 의 코드이고, 프로세스는 `src/apps/` 가 모듈을 조립한 것이다. 모듈 하나가 여러 프로세스에 들고, 프로세스 하나가 여러 모듈을 든다.

```text
 클라이언트(밖) — 브라우저 · 에이전트 · 다른 클라이언트
      │ http                         │ WebSocket — 엔진의 Link 글 넷
      ▼                              ▼
┌ 앞문 front × N ───────┐    ┌ 관문 gate × N ─────────┐
│ 계정 · Api · Static   │    │ 관문                    │         안쪽 망
└──────┬───────────┬────┘    └───┬──────────────┬─────┘  ─────────────────────────
       │ Seat      │             │ Seat         │ Link (그대로 넘긴다)
       ▼           │             ▼              ▼
┌ 제어 control × 1 (+ 대기 1) ───────────┐   ┌ 노드 node × 기계 ──────────────────┐
│ 배치 · 함대 · Operator                  │──►│ 함대(Warden)                        │
│                                         │◄──│   인스턴스 × n                      │
└──────┬──────────────────────────────────┘   │     호스트(엔진, 밖) ◄── Link       │
       │                              Berth   │     NPC 에이전트(엔진, 밖)          │
       │ Ledger · Locker                      └──────┬──────────────────────────────┘
       ▼                                             │ Vault · Locker
┌ 저장 (밖의 제품 — 표는 DB, 디렉터리 · 값은 객체 저장소) ◄───────────────────────┘
```

### 모듈 다섯

| 모듈 | 하는 일 | 모르는 것 | 책임 |
|---|---|---|---|
| 계정 account | 신원을 계정과 캐릭터로 바꾼다. 토큰을 서명하고 푼다. 막힌 계정을 든다 | 존 · 인스턴스 · 프로세스 | [account.md](02-roles/account.md) |
| 관문 gateway | 클라이언트의 소켓을 들고, 그 캐릭터가 놓인 호스트와 글을 그대로 넘긴다. 크기 · 빈도를 지킨다 | 글의 안. 어느 호스트로 갈지 정하는 법 | [gateway.md](02-roles/gateway.md) |
| 배치 placement | 캐릭터를 어느 존의 어느 인스턴스에 놓을지 정하고 기억한다. 자리 · 접속 표 · 대기열 | 프로세스를 띄우는 법. 캐릭터의 값 | [placement.md](02-roles/placement.md) |
| 함대 fleet | 인스턴스를 노드에 띄우고 지키고 내린다. 캐릭터의 값을 인스턴스에 건넨다 | 누가 누구인가. 세계 안 | [fleet.md](02-roles/fleet.md) |
| 저장 storage | 서비스의 표 · 캐릭터의 값과 임대 · 인스턴스의 Store 를 프로세스보다 오래 사는 자리에 둔다 | 값의 안. 누가 어느 자리를 쓰는가 | [storage.md](02-roles/storage.md) |

### 프로세스 넷

| 프로세스 | 든 모듈 | 듣는 것 | 상태 | 늘리는 법 |
|---|---|---|---|---|
| 앞문 front | 계정 · 저장(Ledger) · 함대(Spawner 의 bundle) + Api · Static | 밖의 http | 없음 | 수를 늘린다 |
| 관문 gate | 관문 · 계정(Signer 의 verify) | 밖의 WebSocket | 열린 소켓뿐 — 죽으면 그 사람들이 다시 들어온다 | 수를 늘린다 |
| 제어 control | 배치 · 함대(Fleet) · 계정(Directory · Signer 의 issue) · 저장(Ledger · Locker · Vault 의 사본) + Operator | 안쪽의 Seat · Berth · Operator | 표 — 저장과 보고로 다시 선다 | 하나와 대기 하나. 존의 묶음마다 따로 둘 수 있다(배치의 표는 존마다 갈린다) |
| 노드 node | 함대(Warden) · 저장(Vault · Locker) | 안쪽의 Berth | 이 기계의 인스턴스 | 기계를 늘린다 |

- 엔진의 호스트 · NPC 에이전트는 노드가 띄우는 자식 프로세스다(밖). 저장은 밖의 제품이고 저장 모듈이 그 손이다.
- 뷰어의 묶음 · 실물은 앞문의 Static 이 준다. 앞에 캐시(CDN)를 두어도 모양은 같다.
- 넷을 한 프로세스에 조립한 것이 개발의 `main` 이다 — 소켓이 함수 부름이 될 뿐 흐름은 같다.

### 연결 일곱

선언은 전부 `src/protocol/` 에 있다. 값만 건넌다.

| 연결 | 방향 | 싣는 것 | 선언 |
|---|---|---|---|
| Api | 클라이언트 → 앞문 | 로그인 · 캐릭터 · 입장 | `protocol/api.ts` |
| Link | 클라이언트 ↔ 관문 ↔ 호스트 | 엔진의 글 넷. 관문은 첫 글(`Host 2`)의 자격만 읽고 바꾼다. 나머지는 그대로 | 엔진의 것 — `protocol/engine.ts` |
| Seat | 앞문 · 관문 ↔ 제어 | 앞문의 enter. 관문의 claim · left · beat. 제어의 swap · kick | `protocol/seat.ts` |
| Berth | 제어 ↔ 노드 | 제어의 launch · stop · command · lend · reclaim. 노드의 report · crossed · exited | `protocol/berth.ts` |
| Engine | 노드 → 엔진(밖) | 프로세스의 인자, stdin 의 Console 글, stdout 의 머리글 · status · 건넘 글, 건넴 파일 | `protocol/engine.ts` |
| Vault · Ledger · Locker | 모듈 → 저장 | 자리 · 사본 · 표 · 캐릭터의 값과 임대 | `protocol/vault.ts` |
| Operator | 운영자(밖) → 제어 | 글 한 줄, 답 글 한 줄 | `protocol/operator.ts` |

- 배치와 함대는 같은 프로세스(제어)에 있어도 서로를 import 하지 않는다. 배치는 함대가 내놓은 기능 넷(instances · launch · lend · reclaim)을, 함대는 배치가 내놓은 기능 둘(move · lost)을 앱이 값(함수)으로 넘긴 것으로만 부른다.
- 호스트의 `HOST_AUTH_KEY` 는 제어와 노드가 든다. 관문 · 앞문은 푸는 것(verify)만 한다.

## 앱

앱은 모듈이 아니라 프로세스(밖)의 조립이다. 흐름에서 트리거가 (밖)인 단계만 모듈에 닿는다(경계 규칙 P).

### Service
- 데이터: role:`front`|`gate`|`control`|`node`|`main`(불변) · config(불변) · 그 role 이 든 모듈의 객체 · 듣는 서버.
- 기능: start 는 흐름 1. stop 은 흐름 7. 두 번 불려도 한 번.
- 생애: 프로세스가 만든다. 프로세스와 함께 사라진다.

### Api
- 데이터: server(http) · port(불변) · files(Static).
- 기능: login 은 흐름 2. characters · create · choose 는 흐름 8. enter 는 흐름 3 의 머리. `GET /` 는 들어가는 페이지 한 장. `GET /health` 는 이 프로세스가 듣는가. 그 밖의 GET 은 Static 에 묻는다.
- 생애: 앞문의 Service.start 가 연다. Service.stop 이 닫는다.

### Static
- 데이터: web(엔진 체크아웃의 web 자리) · viewerOut(묶은 viewer.js) · keymap(없으면 null). 전부 불변.
- 기능: serve(path) 는 뷰어의 페이지 · 묶음 · 실물 · Keymap 을 준다. 뿌리 밖은 없다. 파일의 안은 보지 않는다.
- 생애: 앞문의 Service.start 가 만든다.

### Operator
- 데이터: fleet · placement · directory(참조).
- 기능: command(글 한 줄) → 답 글 한 줄. 흐름 6.
- 생애: 제어의 Service.start 가 만든다.

| 메시지 | 방향 | 보내는 것 | 답 |
|---|---|---|---|
| Api login | 클라이언트 → 앞문 | `POST /login {provider, subject?}` | `{token, subject}` 또는 `{why}` |
| Api characters · create · choose | 클라이언트 → 앞문 | `{token}` · `{token, name}` · `{token, character}` | 캐릭터들 · 캐릭터 · `{token}`(캐릭터의 토큰) 또는 `{why}` |
| Api enter | 클라이언트 → 앞문 | `POST /enter {token}`(캐릭터의 토큰) | `{page, gate}` · `{wait: 순번}` 또는 `{why}` |
| Api static | 브라우저 → 앞문 | `GET /play` · `/viewer.js` · `/assets/…` · `/keymap.json` | 파일 |
