# 흐름 5. 주기 작업 — Clock 의 간격

트리거: Clock. 노드 · 컨트롤 플레인 · 게이트웨이가 저마다 제 간격으로.
한 줄: 노드는 캐릭터의 값과 Store 를 저장하고 든 것을 알린다. 게이트웨이는 든 접속을 알린다. 컨트롤 플레인은 그 보고와 제 표를 맞추고, 예비 용량 · 만료 · 대기열을 본다.

## 순서

```text
노드          Console.command → Loader.save → Backuper.backup → NodeReporter.report
게이트웨이      Keepalive.ping → GateReporter.report
컨트롤 플레인   Nodes.heartbeat → Gates.seen → Reconciler.match
              → Nodes.dead → Gates.dead → Scaler.balance → Sessions.expired → Queue.next → Directory.sweep
```

### A 노드

| # | 누가 | 무엇을 | 결과 |
|---|---|---|---|
| 1 | Console.command | 도는 호스트마다 `status` 를 묻는다. 답이 잇달아 없으면 멈춘 것이다 — 끝낸다(⇒ 흐름 4) | 사람 수 · 지연 |
| 2 | Loader.save | 저장 주기마다, 로드된 캐릭터 전부의 값을 저장한다 | 캐릭터의 값 |
| 3 | Backuper.backup | 백업 주기마다, 도는 호스트의 Store 사본을 올리고 백업을 남긴다 | 존의 값의 백업 |
| 4 | NodeReporter.report | 인스턴스마다 state · 사람 수 · 지연 · 로드된 캐릭터들을 알린다 | |

### B 게이트웨이

| # | 누가 | 무엇을 | 결과 |
|---|---|---|---|
| 5 | Keepalive.ping | 접속마다 ping. 답이 없으면 닫는다(⇒ 흐름 11) | |
| 6 | GateReporter.report | 접속마다 캐릭터와 이어진 인스턴스를 알린다 | |

### C 컨트롤 플레인

| # | 누가 | 무엇을 | 결과 |
|---|---|---|---|
| 7 | Nodes.heartbeat | 노드의 보고를 적는다 | |
| 8 | Gates.seen | 게이트웨이의 보고를 적는다 | |
| 9 | Reconciler.match | 보고와 표가 어긋난 것을 고친다 — 표에 없는 인스턴스는 내리게 하고, 표에는 도는데 보고에 없는 인스턴스는 죽은 것이고(⇒ 흐름 12), 세션과 로드 · 접속이 어긋난 것을 맞춘다 | 표가 실제와 같다 |
| 10 | Nodes.dead | 보고가 끊긴 노드의 인스턴스는 죽은 것이다 | ⇒ 흐름 12 |
| 11 | Gates.dead | 보고가 끊긴 게이트웨이의 세션은 끊긴 것이다 | ⇒ 흐름 11 의 2 |
| 12 | Scaler.balance | 존마다 예비 용량이 모자라면 띄우고(⇒ 흐름 3 의 B), 쉬는 인스턴스와 다 비운 인스턴스는 내린다(⇒ 흐름 7 의 3 ~ 6) | |
| 13 | Sessions.expired | `pending` 인 채 만료된 세션은 지운다. `grace` 가 만료된 세션은 값을 언로드한다 | ⇒ 흐름 11 의 3 |
| 14 | Queue.next | 슬롯이 난 존마다 기다리던 사람의 세션을 잡는다(흐름 3 의 7). 오래 묻지 않은 사람은 Queue.drop 으로 줄에서 뺀다 | |
| 15 | Directory.sweep | 하루에 한 번, 캐릭터가 없고 오래 오지 않은 계정을 지운다 | |

## 실패하면

- 스토리지에 닿지 않으면 2 · 3 은 다음 주기에 다시 한다. 4 의 보고는 그것과 따로 간다 — 저장이 밀려도 노드는 살아 있다고 알린다.
- 2 의 저장이 거절되면(그 캐릭터의 lease 를 잃었다 — 다른 곳에 배정됐다) 그 묶음을 세계에서 지운다.
- 컨트롤 플레인 쪽 망이 끊겨 노드의 큰 몫이 한꺼번에 끊겨 보이면 10 을 하지 않는다. 죽음의 판정은 운영자가 한다(흐름 6 의 `forget`).

## 멈추는 자리

- 캐릭터의 값이 스토리지에(마지막으로 저장한 것). 컨트롤 플레인의 표가 노드 · 게이트웨이가 든 것과 같다.

## 이어지는 흐름

- 3 · 7 · 11 · 12.

## 규칙

- 진실은 노드가 든 것(로드된 캐릭터)과 게이트웨이가 든 것(접속)이다. 컨트롤 플레인의 표는 그 보고와 맞춘 것이다 — 알림 하나가 사라져도 다음 보고가 바로잡는다.
- 호스트가 죽으면 캐릭터는 마지막으로 저장한 값으로 돌아간다. 저장 주기가 유실의 크기다.
- 도는 인스턴스의 Store 자리를 그대로 올리지 않는다. 올리는 것은 엔진이 `backup` 으로 낸 사본이다.
