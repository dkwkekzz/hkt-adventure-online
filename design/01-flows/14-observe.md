# 흐름 14. 관측 — 수집기의 요청

트리거: 밖의 수집기 · load balancer 의 http 요청. 프로세스마다의 `GET /health` 와 `GET /metrics`.
한 줄: 프로세스가 제 일을 할 수 있는가를 답하고, 제 수치를 글로 낸다. 판단과 알림은 수집기(밖)의 일이다.

## 순서

```text
GET /health  → Monitor.health
GET /metrics → Monitor.metrics
```

| # | 누가 | 무엇을 | 결과 |
|---|---|---|---|
| 1 | Monitor.health | 이 프로세스가 듣고 있는가. 내려가는 가운데면 503 — load balancer 가 새 요청을 다른 곳으로 보낸다. 컨트롤 플레인은 활성인지 대기인지도 답한다 | 200 또는 503 |
| 2 | Monitor.metrics | 그 role 의 수치 — API 서버: 요청 · 거절의 수. 게이트웨이: 열린 접속 · 버린 글. 컨트롤 플레인: 존마다 세션 · 대기열 · 빈 슬롯, 인스턴스마다 state · 사람 수 · 틱 지연. 노드: 인스턴스마다 state · 틱 지연 · 마지막 저장 뒤의 시간 | 글 |

## 실패하면

- 없음. 답하고 끝난다. 상태를 바꾸지 않는다.

## 규칙

- 답에 계정 · 캐릭터의 이름과 토큰이 없다. 수와 state 뿐이다.
- 수치는 그 프로세스가 이미 든 것이다. 관측을 위해 다른 프로세스에 묻지 않는다.
- load balancer 가 빼는 것은 새 접속을 받을 자리뿐이다. 이미 열린 접속은 건드리지 않는다.
